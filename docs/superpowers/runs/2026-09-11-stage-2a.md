## Rulings made by the controller

- Reads are allowed anywhere; the earlier `/scan` 403 test became an "indexes outside the sandbox"
  test. The sandbox default moved to `FILEPLUS_APP_DIR/FilePlusTestSandbox`, so each worktree gets its
  own empty sandbox. Cost if wrong: one config default.
- Expected test counts in the plan were arithmetic estimates; implementers reported actual counts (153
  at the end) and never chased the number.
- Crash reconciliation classifies path-less and `:final` rows (mkdir/touch, config/tag/favorite/pin,
  trash-empty) as completed or not-started rather than "ambiguous".
- The mover safety audit (Opus) drove six fixes: replace-trash shares the operation's batch; moving a
  file into its own folder is refused; copy verification compares full trees including empty
  directories and hashes files up to 1 GiB; computed trash paths are guarded and `empty_trash` skips
  roots the guard refuses; reserved device names are rejected by stem (`con.txt` is now invalid — this
  overrode the plan's own test); the trash-root probe survives stale network drives. The batch
  directory is now created inside the logged action.
- Undo of a keep-both move restores the original basename when free; if that corrective rename fails
  the undo still succeeds and the item stays under the keep-both name.
- `/drives` lists fixed volumes only (the plan's filter would have admitted USB and network drives).
- Reorder endpoints re-pack positions from a partial list; re-pinning is idempotent; unknown pin ids
  return 404.
- Text preview is a bounded 4 KB read; the quick-index task reference is held; stale-row removal is
  scoped to the indexed root; tag operations log before acting and mark executed.

## Known debts (deferred to Stage 2B/3)

Migrations use bare `except Exception`; `is_under` has no drive-root test; `/health` `db_ok` conflates
connectivity with the pending query; error details embed full paths and CORS is `*` (localhost only);
tree-level copy verification hashes every file <= 1 GiB (I/O cost); `_hide` only on trash-root creation;
`undo_batch` returns a minted batch id even when every op errors; single-op undo of a replace-move
leaves the replaced file in trash (batch undo handles it); undo trusts the logged path, not a hash;
duplicated reorder bodies; `recent_groups` tie-break depends on microsecond timestamps; tag names
case-sensitive; LIKE wildcards unescaped in search; `DELETE` tag no-op on unknown id; index
done-callback untested; folder-mounted volumes / junction moves fall back to an error instead of
copy-verify-remove.
