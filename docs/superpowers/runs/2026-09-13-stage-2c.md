This run turned the author's day-of-use playtest notes into a refinement pass inside Stage 2: real
tabs, a custom FilePlus file-type icon family (with a Windows-icon option and shell thumbnails), a
rebuilt search (live in the current folder, indexed for "This PC"), a from-scratch Properties panel
with a native-dialog escape hatch, pointer-based drag and drop with Move/Copy semantics, a real This
PC / Quick Access sidebar, View/Sort menus, and the visible (unwired) shell for Stage 3's AI entry
point, Ask File+. Sixteen tasks, one autonomous run, one commit per task plus fix rounds where review
found defects.

## What landed, per task

- **Task 1 — file-type taxonomy + platform plumbing.** `backend/filetypes.py` (families/groups, the
  single source of truth), `GET /filetypes`, `GET /known-folders` (`SHGetKnownFolderPath`), `GET
  /fs/peek` (capped folder-preview listing), `GET /index/status`; `FILEPLUS_PORT` threaded through
  `backend/api.py`, `frontend/main.js`/`preload.js` (`apiPort()`), `api.js`, and the smoke harness so
  `verify.ps1` can run its own backend on 9877 beside a developer's live one on 9876. Fix round 1:
  `DELETE /index` guards, lazy `/fs/peek` scan, a `winshell` buffer-free bug.
- **Task 2 — live tree search.** `GET /fs/search` (bounded `os.scandir` walk, type/ext/modified/
  size/tag/hidden/whole-word filters, 4 s budget) and index-backed search filters for the "This PC"
  scope. Fix round 1: per-entry budget check, deterministic scandir close, case-insensitive tag
  matching, a `/search` SQL cap.
- **Task 3 — properties/attributes/folder-type backend.** `GET /fs/properties`, `GET
  /fs/properties/details` (shell property store via `pywin32`, 503 when absent), `POST
  /fs/attributes`, `POST /fs/folder-type` — all logged and undoable. Fix round 1: undo went through
  `path_guard`, folder-bits-exact restore, BOM-aware `desktop.ini` surgery, unsigned ctypes
  composition for attribute bit flags.
- **Task 4 — Electron bridge.** File icons, shell thumbnails, and native Properties/Open-with dialogs:
  `electronAPI.fileIcon`, `.thumbnail`, `.showProperties`, `.openWithDialog`. Fix round 1: reject
  control characters in paths, guard empty icon/thumbnail images.
- **Task 5 — Fluent chrome icon sprite.** `frontend/assets/fp-icons.svg`, the `icon()` helper, and
  `scripts/check_icons.js` (no hand-drawn inline `<svg>` outside the sprite; every reference resolves;
  every file-type family has a symbol).
- **Task 6 — FilePlus file-type icon family.** The custom icon set (35 families + 9 folder variants),
  `ui.icon_source` (fileplus/windows), thumbnails via the shell, fanned folder previews. Fix round 1:
  known-folder path fixes, bounded icon caches, light-theme tab contrast, `/fs/peek` capped at 200.
- **Task 7 — real tabs.** Per-tab state (`{id, screen, label, path, history, view, scrollTop,
  selection}`), duplicate/close-others, drive labels without a flash, the sidebar as single source of
  truth for active-path highlighting. Fix round 1: guard `loadDirectory` against superseded fetches,
  copy `scrollTop` on duplicate, gitignore `test-results`, log console-error locations.
- **Task 8 — inspector switch, deselect, refresh, theme, density.** `ui.inspector_open` as the only
  thing that opens/closes the Inspector; fixed geometry so it never jitters; deselect-anywhere;
  refresh button beside the breadcrumb; one-click theme toggle; the missing "Spacious" density CSS
  rule. Fix round 1: marquee Ctrl/Shift-drag vs. deselect-anywhere race, inspector path ellipsis, meta
  grid row count.
- **Task 9 — This PC, Quick Access, Backspace setting.** This PC sidebar section (collapsible drive
  list), `GET /known-folders`-backed Quick Access defaults (Desktop/Downloads/Screenshots, removable),
  `ui.backspace_deletes`. Fix round 1: narrowed the sidebar keydown guard to Enter/Space only.
- **Task 10 — list scale, View/Sort menus, List view, dynamic media view.** Explorer-only Ctrl+wheel
  `--list-scale`, View and Sort toolbar dropdowns built on the context-menu component, a name-only
  List view, and dynamic media view (grid-at-Medium when a folder is majority images/video). Fix
  round 1: carried the keyboard-guard fix forward with a smoke assertion.
- **Task 11 — selection visuals, menu applicability, favorites.** Edge-hugging selection with merged
  borders on adjacent rows, `enabled(ctx)` predicates on context-menu items, the favorites star and
  Add/Remove label toggle. Fix round 1: F2/menu single-item rename parity, folder-only
  open-in-new-tab, sequential multi-open.
- **Task 12 — pointer-based drag and drop.** HTML5 drag/drop replaced with an in-app pointer-event
  session (a floating Move/Copy badge, modifier-key overrides, spring-loaded folders, right-click-up
  during a drag) — the ruling being that Chromium cancels a native drag on right-click and gives no
  control over the ghost.
- **Task 13 — Properties panel.** `properties.js` and `#properties-modal`: General/Details tabs,
  attribute checkboxes, the folder-type select ("Optimize this folder for"), "Opens with" + Change…
  (native Open-with dialog), Advanced… (native Properties dialog), `ui.properties_mode` switching the
  whole feature to the Windows-native dialog.
- **Task 14 — search overhaul, Scan & Index, sidebar tags.** Discord-style filter chips, live results
  rendered in the Browser list, a This PC scope chip backed by the index, real `GET /index/status`
  data in Settings › Scan & Index (Re-index / Remove-from-index per root), and `GET /tags` wired into
  the sidebar TAGS chips (top 8 by count, click → This PC search scoped to the tag). Fix round 1:
  tab-supersession guard, no-overflow narrow toolbar, Up/Backspace exit search.
- **Task 15 — Ask File+, Tag Canvas banner.** The sidebar pill button, its popout shell (textarea,
  example-prompt chips, a disabled Send with a "AI arrives in Stage 3" tooltip), and the "Not built
  yet — planned for Stage 3" banner over the Tag Canvas's dimmed mock body.
- **Task 16 — this task.** The filetypes parity gate in `verify.ps1`, CLAUDE.md's module map and
  bridge-method notes, one-line integration-ledger marks, this run summary, and the carried
  focus-return fix below.

  if wrong: one extra review cycle.
- `/fs/peek` returns `{items: []}` for a missing or non-directory path (best-effort preview, keeps the

- (From `home.png`) sidebar TAGS chips were static demo markup — placeholder debt the author read as
  "tags not implemented." Task 14 wires them to `GET /tags` (top 8 by count; click → This PC search

- The Task-9 keyboard-guard fix was carried into Task 10 (same file) with a keyboard smoke assertion
  — cost if wrong: one extra review cycle.
- "Open in new tab" is folder-only (Explorer parity). Hide bucket = items that can never apply to the

- All three Task-14/15-adjacent rulings carried to Task 15 (smoke/styles touched there) — cost if

## Known debts (not fixed in 2C)

- `/search` (This PC scope) is the weaker half: match spans recomputed client-side, `hidden`
  approximate (name prefix only), `type: folder` never matches on the index, results in folder sort
  not relevance, "drives not indexed" hint counts a drive as indexed if any root lies on it.
- A truncated live search cannot distinguish "hit the cap" from "timed out" (both `truncated`).
- Chips that scroll out of the search bar can only be removed with Backspace.
- Cross-volume Copy default is only exercised via Ctrl in the sandbox (single volume); `sameVolume`'s
  UNC branch is unproven on real shares.
- Click-swallow after a drop is a 300 ms / 8 px heuristic.
- `manualViewByPath` (dynamic media view override) is session-only, never persisted.
- Settings › Quick Access checkboxes cover desktop/downloads/screenshots only.
- `pins_add` undo-of-remove recreates the pin with a default label (Stage 2B debt).
- `saveSetting` is fire-and-forget; rapid same-key changes can revert `__fpConfig` on a transient
  failure (Stage 2B debt).
- Toolbar at 800 px with a 480 px sidebar fits with ~14 px to spare; any new toolbar button needs the
  narrow mode re-checked.
- Native Properties / Open-with dialogs spawned from the app could not be visually confirmed from the
  agent sandbox (mechanism verified by direct invocation) — **author hands-on check at graduation**
  (see "How to review" below).
- The one-off "console 404 on a cold verify run" was never reproduced (10+ clean runs); the smoke now
  records the URL of any console error.
- Eight code families share the `</>` glyph (colour-only separation); pdf/powerpoint share a `P`
  glyph.
- No focus trap in any modal (pre-existing convention).
