## 5. Recommendations

**Tokens are in excellent shape.** All 68+ canonical tokens are present with correct values. The `:root` block is the strongest part of this file — zero fixes needed there. The light-mode `[data-theme="light"]` overrides are also complete and correct.

**Components are mostly present but have three systemic problems.** First, the file has a structural split: a clean `fp-*` component layer (lines 1–2028) and a second layer of non-prefixed layout and screen classes (lines 2029–4228) that partially duplicates it. At least five classes (`fp-modal`, `fp-toast`, `fp-pill`, `fp-chip--add`, `fp-input`) are defined twice with differing values; in each case the later definition wins in the cascade, making the earlier one dead code. Second, the `.aq-btn` block at line 2260 is a broken legacy Approvals pill implementation using a purple-blue gradient — it contradicts the spec completely and should be deleted. Third, `fp-chip` uses the wrong default background (`bg-pressed` instead of `bg-raised`) and is missing a border — the spec calls for `raised` bg + `border-subtle` 1px border + no `box-shadow` at rest.

**Missing components and undefined tokens are limited but actionable.** `fp-kbd-pill` and `fp-drag-handle` are the only fully absent component classes. Three tokens (`--r-sm`, `--ease-ui`, `--track-heading`) are referenced in screen-specific sections but never defined — these will silently fail. Downstream task S3 or the relevant screen-pass task should add them to `:root` or replace references with their canonical equivalents (`--r-chip`, `--ease-snap`, `--track-caps`).
